# GI전자 리뉴얼 레퍼런스 분석

이 문서는 사용자가 제공한 `index-visual`, `INDEX`, Typography, Color System, 서브페이지 시안, 전체메뉴 시안을 기반으로  
GI전자 사이트를 `그대로 복제하지 않고`, 브랜드 연속성을 유지한 채 재해석하기 위한 기준 문서다.

## 1. 결론 먼저

- 이 레퍼런스의 핵심은 `산업용 전자/제조 B2B 브랜드의 신뢰감`이다.
- 메인은 `어두운 몰입형 히어로`, 서브는 `밝고 정돈된 정보형 레이아웃`으로 이중 톤을 가진다.
- 브랜드 포인트는 `강한 블루`, `헤비한 화이트 타이포`, `정밀하고 절제된 UI`다.
- 복제하면 안 되는 부분은 `슬라이드 구성 자체`가 아니라 `암부 중심의 프레임`, `정보 위계`, `메뉴 구조`, `B2B 톤`이다.
- 새 제품소개는 옛 사이트의 텍스트 자산을 살리되, 레이아웃은 `카탈로그 + 제품 상세` 구조로 완전히 재설계하는 것이 맞다.

## 2. 레퍼런스가 말하는 브랜드 인상

### 2.1 핵심 키워드

- 신뢰
- 정밀
- 산업 기술력
- 유지보수/사후관리
- 커스텀 제작
- 차분하지만 강한 자신감

### 2.2 시각적 인상

- 메인 히어로는 `사진 + 어두운 오버레이 + 대형 카피`로 브랜드 인상을 먼저 각인시킨다.
- UI 장식은 거의 없고, 대신 `로고`, `주메뉴`, `햄버거 메뉴`, `슬라이드 프로그레스`, `스크롤 유도` 같은 기능성 요소만 남긴다.
- 기업 사이트인데 과하게 보수적이지 않고, 제조/기술 기업에 맞는 현대적 긴장감이 있다.
- 즉, 감성적인 라이프스타일 브랜드가 아니라 `기술 파트너`의 표정을 가져야 한다.

## 3. 타이포그래피 분석

## 3.1 제공된 기준

- 국문/영문/숫자 기본체: `Pretendard`
- 영문 보조 워드마크/짧은 라벨: `Nexa`
- 국문 카피는 Pretendard의 Medium, SemiBold, Bold 계열이 중심
- 영어 브랜드명이나 짧은 슬로건은 Nexa Heavy가 효과적

## 3.2 왜 이 조합이 맞는가

- `Pretendard`는 한국어 UI와 본문 가독성이 좋고, 정보성 페이지에서 밀도 높은 텍스트를 처리하기 쉽다.
- `Nexa`는 짧은 영어 라벨과 브랜드 보조 문구에 쓰면 기술적이고 각진 인상을 준다.
- 즉, `본문과 UI는 Pretendard`, `영문 강조 라벨만 Nexa`로 분리해야 세련되다.

## 3.3 그대로 쓰면 안 되는 방식

- Nexa를 긴 한국어 본문에 섞는 것
- 모든 제목을 지나치게 굵게 써서 무게감을 남발하는 것
- 영어와 국문이 같은 역할을 하는데 서로 다른 폰트를 무분별하게 사용하는 것

## 3.4 추천 적용 방식

- H1: Pretendard 700~800
- H2: Pretendard 700
- H3: Pretendard 600~700
- Body: Pretendard 400~500
- Eyebrow / English accent: Nexa Heavy 또는 Pretendard 600 영문 대체
- 메뉴: Pretendard 500~600
- 데이터/숫자: Pretendard 500, 필요한 경우 tabular 처리

## 3.5 추천 스케일

- Hero headline: `clamp(40px, 5vw, 72px)`
- Section title: `clamp(28px, 3vw, 48px)`
- Sub title: `24px ~ 32px`
- Body large: `18px / 30px`
- Body base: `16px / 28px`
- Caption / meta: `13px ~ 14px`

## 4. 컬러 시스템 분석

## 4.1 제공된 팔레트

- Blue `#167BFF`
- Yellow `#FFB612`
- Purple `#6901D8`
- Red `#D02738`
- Light Blue `#E8F5FF`
- Black `#111111`
- Gray `#333333`, `#666666`, `#999999`, `#CCCCCC`, `#F2F2F2`
- White `#FFFFFF`

## 4.2 실제로 살아 있는 색

레퍼런스 전체를 보면 실질적인 주연은 아래 세 가지다.

- `Black / White`
- `Brand Blue`
- `Gray scale`

Yellow, Purple, Red, Light Blue는 시스템상 보조색으로 보이고, 현재 메인 시안에서는 사실상 거의 쓰이지 않는다.

## 4.3 추천 사용 원칙

- 블루는 브랜드 주색이지만 `면 전체를 칠하는 색`보다는 `강조선, 버튼, 링크, 포인트 카피, 진행 상태`에 써야 힘이 산다.
- 보조 색상은 페이지 전체 톤을 바꾸는 데 쓰지 말고, 상태나 특정 카테고리 구분 정도로 제한해야 한다.
- 메인페이지는 `검정 기반`, 서브페이지는 `화이트 기반`으로 나눠 쓰는 편이 레퍼런스와 가장 잘 맞다.

## 4.4 추천 토큰 해석

- `--color-bg-dark: #0b0e12`
- `--color-bg-elevated: #111111`
- `--color-bg-light: #ffffff`
- `--color-bg-subtle: #f6f8fb`
- `--color-text-strong: #111111`
- `--color-text-inverse: #ffffff`
- `--color-text-muted: #666666`
- `--color-border: #e5e8ee`
- `--color-brand: #167BFF`
- `--color-brand-soft: #E8F5FF`
- `--color-brand-2: #6901D8`
- `--color-danger: #D02738`
- `--color-warning: #FFB612`

## 4.5 피해야 할 것

- 보조색을 무지개처럼 동시에 많이 쓰는 것
- 흰 바탕 페이지에 너무 진한 블루 면을 과하게 까는 것
- 메인과 서브 모두 같은 배경 톤을 써서 구조적 대비를 없애는 것

## 5. 레이아웃과 컴포넌트 패턴 분석

## 5.1 메인페이지 패턴

- `풀블리드 히어로 슬라이드`
- `투명/반투명 상단 헤더`
- `왼쪽 정렬 대형 카피`
- `프로그레스형 슬라이드 컨트롤`
- `스크롤 유도 버튼`
- `제품 카드 섹션`
- `검색 또는 빠른 진입 밴드`
- `뉴스/공지 리스트`
- `문의 CTA 밴드`
- `진한 다크 푸터`

## 5.2 서브페이지 패턴

- 상단 히어로 배너
- 대분류 기준 페이지 타이틀
- 2차 탭 또는 서브내비
- 화이트 배경 중심의 본문
- 좌우 분할 또는 리스트 구조

## 5.3 게시판 패턴

- 공지사항: `리스트 -> 상세`
- 자유게시판: `리스트 -> 상세 -> 작성`
- 검색 박스, 날짜, 제목, 페이지네이션, 이전/다음 네비게이션이 중요

## 5.4 전체메뉴 패턴

- 대분류를 먼저 보여준다
- 각 대분류 아래 하위 메뉴를 한 번에 열람한다
- 단순한 햄버거 드로어보다 `전체 화면 오버레이`가 더 잘 맞는다
- 다크 오버레이를 써도 좋지만, 현재 레퍼런스처럼 화이트/다크 두 가지 버전 실험이 가능하다

## 6. 페이지별 해석

## 6.1 메인 랜딩

보존해야 할 것:

- 3장 수준의 대표 비주얼 슬라이드
- 블루 포인트 라벨
- 대형 화이트 카피
- 상단 네비게이션의 절제된 배치

개선해야 할 것:

- 슬라이드 자체보다 `핵심 가치`, `대표 제품군`, `문의`가 더 빠르게 연결되게 해야 한다
- 제품 섹션 카드 밀도와 정보 위계를 더 명확히 해야 한다
- 뉴스와 CTA 사이의 시각적 전환을 더 매끄럽게 해야 한다

## 6.2 인사말 / 연혁 / 오시는길

- 세 페이지는 하나의 `회사소개 허브` 아래 있어야 한다
- 상단 히어로와 탭 구조는 통일되어야 한다
- 인사말은 `대표 메시지`, 연혁은 `연대기`, 오시는길은 `지도/연락처/교통 정보`로 역할을 분리해야 한다
- 현 시안의 화이트 기반과 얇은 블루 탭 라인은 유지 가치가 높다

## 6.3 제품소개

- 현재 시안은 빈 상태에 가까워 정보구조가 아직 덜 잡혀 있다
- 옛 사이트는 `콘텐츠는 풍부하지만 레이아웃은 낡은 카탈로그`다
- 따라서 새 제품소개는 `허브 -> 제품군 -> 상세` 구조로 재설계해야 한다
- 메인에서 보여주는 제품 카드와 같은 데이터 소스를 보도록 설계하는 것이 맞다

## 6.4 공지사항 / 자유게시판

- 시안의 기본 뼈대는 무난하다
- 다만 공지와 자유게시판을 거의 같은 컴포넌트로 만들 수 있게 구조를 맞추는 편이 좋다
- 차이는 `공지 여부`, `작성 가능 여부`, `검색/정렬`, `버튼 강조` 정도면 충분하다

## 6.5 전체메뉴

- 가장 중요한 건 `정보구조를 압축해서 보여주는 것`이다
- 현재 시안처럼 대분류 4개를 먼저 놓고 하위 메뉴를 정리하는 방식이 적절하다
- 단, 오버레이 디자인은 사이트 전체 톤에 맞게 더 고급스럽게 정리할 수 있다

## 7. 반드시 계승할 요소

- 암부가 강한 메인 히어로
- 브랜드 블루 포인트
- 강한 국문 헤드라인
- 상단 주메뉴 + 햄버거 전체메뉴 구조
- 메인과 서브의 톤 차이
- B2B 제조/전자 기업다운 절제된 UI

## 8. 그대로 가져오면 안 되는 요소

- 과거 외주 시안의 배치와 컴포넌트 비율을 그대로 따라가는 것
- 옛 제품소개의 테이블형, 나열형, 사이드바 중심 구조
- 작은 텍스트를 촘촘하게 깔아 넣는 레이아웃
- 시안마다 조금씩 다른 규칙으로 만든 탭/헤더/콘텐츠 폭

## 9. 새 사이트에서 더 좋아져야 하는 부분

- 모바일 대응
- 접근성 대비
- 공통 템플릿화
- 제품 데이터 구조화
- 게시판 패턴 공통화
- CTA 명확성
- 메인과 서브 간 전환의 자연스러움

## 10. 제품소개 리뉴얼 방향

### 10.1 옛 사이트에서 가져올 것

- 제품명
- 핵심 특징
- 적용 분야
- 사양
- 이미지
- 외부 원문 참조 정보

### 10.2 버릴 것

- 오래된 사이드바 구조
- 텍스트 나열형 레이아웃
- 제품마다 긴 본문을 목록에서 다 보여주는 방식

### 10.3 새 정보구조

- 제품 허브
- 제품군 필터
- 제품 카드
- 제품 상세
- 원문 보기 또는 레거시 참조
- 문의 연결

## 11. 현재 코드에 적용할 때의 핵심 판단

- 현재 저장소는 레퍼런스의 `브랜드 톤`만 일부 가지고 있고, `정보 구조`와 `공통 템플릿`은 거의 없다
- 따라서 단순 CSS 덧칠이 아니라 `레이아웃 구조`, `콘텐츠 모델`, `컴포넌트 체계`를 같이 갈아야 한다
- 우선순위는 `헤더/히어로/섹션 타이틀/서브 페이지 템플릿/제품 데이터 구조` 순서가 맞다
